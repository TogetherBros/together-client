# Together — 구현 기획서

> 버전: v0.1  
> 목표: 7일 내 로컬 MVP 완성  
> 플랫폼: Windows / macOS  
> 스택: Tauri v2 + React + TypeScript / Spring Boot + WebSocket

---

## 1. 서비스 개요

친구들이 같은 "방"에 접속하면, 서로의 바탕화면 위에 이모지 캐릭터로 나타나는 데스크탑 오버레이 앱. 창 없이 바탕화면 자체에 렌더링되며, 현재 어떤 앱을 쓰는지 자동으로 감지해 말풍선으로 표시한다.

---

## 2. 핵심 기능 정의

### 2-1. 방 생성 및 입장
- 앱 실행 시 닉네임, 이모지, 방 코드를 입력하는 설정 화면이 뜬다.
- 방 코드는 직접 입력하거나 새로 생성할 수 있다.
- 같은 방 코드를 입력한 유저끼리 같은 세션에 연결된다.
- 회원가입 없이 바로 시작한다. 유저 정보는 세션 동안만 유지된다.

### 2-2. 오버레이 렌더링
- 입장 후 설정 화면은 사라지고, 바탕화면 위에 투명한 오버레이만 남는다.
- 같은 방의 다른 유저들이 이모지 캐릭터 + 닉네임 + 활동 말풍선 형태로 표시된다.
- 내 캐릭터도 내 화면에 표시된다.
- 캐릭터는 화면 하단에 유저 수에 따라 자동으로 분산 배치된다.
- 오버레이는 클릭을 방해하지 않는다. 마우스 이벤트가 오버레이를 통과한다.

### 2-3. 활동 감지
- 3초마다 현재 포커스된 앱/창 이름을 OS에서 읽어온다.
- 앱 이름을 사람이 읽기 좋은 텍스트로 변환해 말풍선에 표시한다.
- 매핑 예시:

| 감지된 앱 | 표시 텍스트 |
|-----------|------------|
| YouTube (Chrome 탭 제목) | 유튜브 보는 중 |
| IntelliJ IDEA | IntelliJ 하는 중 |
| VS Code | 코딩 하는 중 |
| Spotify | 음악 듣는 중 |
| Discord | 디스코드 하는 중 |
| 그 외 | [앱 이름] 하는 중 |
| 감지 실패 | 작업 중... |

### 2-4. 실시간 동기화
- 유저의 활동 상태가 변경되면 같은 방의 모든 유저에게 즉시 반영된다.
- 유저가 방을 나가거나 앱을 종료하면 해당 캐릭터가 사라진다.
- 연결이 끊기면 자동으로 재연결을 시도한다.

### 2-5. 시스템 트레이
- 앱이 실행 중일 때 시스템 트레이에 아이콘이 표시된다.
- 트레이 아이콘 우클릭 → 방 나가기 / 종료 메뉴 제공.

## 3. 화면 구성

### 화면 1 — 입장 설정 화면
앱 최초 실행 시 표시. 입장 완료 후 사라짐.

- 닉네임 입력 (최대 8자)
- 이모지 선택 (그리드로 선택)
- 방 코드 입력 또는 새 방 생성 버튼
- 입장 버튼

### 화면 2 — 오버레이 (메인)
입장 후 항상 표시. 바탕화면 위에 투명하게 떠 있음.

- 친구 캐릭터들 (이모지 + 닉네임 + 활동 말풍선)
- UI 없음. 트레이로만 제어.

---

## 4. 데이터 구조

### 유저 상태 (세션 동안 유지)

| 필드 | 설명 |
|------|------|
| userId | 앱 실행마다 생성되는 임시 고유 ID |
| nickname | 유저가 입력한 닉네임 |
| emoji | 선택한 이모지 |
| activity | 현재 활동 텍스트 |

### 서버 인메모리 구조

| 구조 | 설명 |
|------|------|
| rooms | 방 코드 → 유저 목록 Map |

DB 없음. 서버 재시작 시 모든 세션 초기화.

## 5. 통신 구조

```
클라이언트 A                서버                클라이언트 B
     │                       │                       │
     │── 방 입장 메시지 ──▶  │                       │
     │                       │◀── 방 입장 메시지 ───  │
     │                       │                       │
     │◀── 유저 목록 broadcast ──────────────────────▶ │
     │                       │                       │
     │── 활동 업데이트 ─────▶ │                       │
     │                       │◀──────────── 활동 업데이트│
     │◀── 전체 상태 broadcast ──────────────────────▶ │
```

- 클라이언트 → 서버: 입장, 활동 업데이트, 퇴장
- 서버 → 전체: 유저 목록 변경 시 broadcast
- 프로토콜: WebSocket + STOMP

## 6. 7일 구현 일정

### Day 1 (월) — 기반 세팅
- Spring Boot 프로젝트 생성, WebSocket/STOMP 설정
- 방 생성/입장/퇴장 로직 구현 (인메모리)
- Tauri 프로젝트 생성, 투명 오버레이 창 설정

### Day 2 (화) — 연결
- 입장 설정 화면 UI 구현
- 클라이언트 ↔ 서버 WebSocket 연결
- 입장/퇴장 메시지 송수신 확인

### Day 3 (수) — 오버레이 렌더링
- 유저 목록을 받아 캐릭터를 오버레이에 렌더링
- 이모지 + 닉네임 + 말풍선 UI

### Day 4 (목) — 활동 감지
- Rust에서 OS API로 활성 창 이름 읽기 (Windows + macOS)
- 앱 이름 → 활동 텍스트 매핑 로직
- 3초마다 서버에 활동 상태 전송

### Day 5 (금) — 마무리 로직
- 캐릭터 위치 자동 분산 배치
- 시스템 트레이 아이콘 및 메뉴
- 연결 끊김 시 자동 재연결

### Day 6 (토) — 테스트 및 버그 수정
- 2명 이상 실제 접속 테스트
- 엣지케이스 처리 (창 감지 실패, 방 코드 오류 등)
- 전반적인 버그 수정

### Day 7 (일) — 다듬기
- 캐릭터 등장/퇴장 애니메이션
- 말풍선 전환 애니메이션
- 친구에게 보여줄 수 있는 수준으로 마무리

## 7. MVP 범위

### 포함
- 방 생성 및 입장 (코드 기반)
- 바탕화면 오버레이 렌더링
- 활동 자동 감지 및 표시
- 실시간 동기화
- 시스템 트레이

### 제외 (이후 버전)
- 채팅 / 음성 통화
- 캐릭터 커스터마이징 (애니메이션, 움직임)
- 계정 저장 / 로그인
- 자동 업데이트
- 배포 (코드사이닝)
